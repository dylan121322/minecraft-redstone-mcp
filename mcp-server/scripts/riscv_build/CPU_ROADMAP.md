# RISC-V 8-bit CPU → Minecraft Redstone — 完整路线图

目标:把 ujjwal-2001/RISCV_8bit_pipeline(5 级流水线 CPU)建进 Minecraft 纯红石。
流程:现实代码 → 提取单元 → 红石重构 → 模拟 → 实践(游戏内建造)。

服务器:frp-tag.com:40269(creative,vanilla 1.21.4,无 MC-31100 mod)。

---

## 分层状态

### ✅ 层 0:物理原语与验证链(完成)
- 6 门标准单元(NOT/BUF/AND/OR/NAND/NOR)——游戏内各 4/4 验证
- via 爬升 y0→y2→y4、H/V 层交叉隔离、下降 staircase、descent-into-pin——MCHPRS + 游戏内验证
- `/setblock` 建造机制:无方块更新→dust 驱动输入、repeater-via 换层、速率 200ms、距离 ≤210
- 分层验证(物理 per-cell + 逻辑 netlist)绕开 MCHPRS 全芯片仿真瓶颈
- yosys+abc 综合、numpy bit-parallel 仿真(120K vec/s)

### 🔧 层 1:模块级布线器(差最后一步 — 当前攻关)
- 6 个组合模块已综合 + 逻辑验证(Control/ALU/ALU_Control/Mux/Forwarding/Imm_Gen,399 门)
- 2 层曼哈顿架构验证成立;短路收敛 1292→749→281
- **唯一阻塞**:通道布线垂直约束轨道分配(y4 列按 sink-x 共享→重叠)。详见 [[riscv-redstone-router-bug]]
- 完成即可游戏内建造任一**组合**模块

### ❌ 层 2:时序元件(未开始 — 完整 CPU 的关键缺口)
当前所有模块都是**组合逻辑**(无记忆)。5 级流水线 CPU 需要:
- **D 触发器 cell**:cell 库目前只有 RS 锁存/T 触发器目录条目,无验证过的边沿触发 D-FF。需设计 + MCHPRS + 游戏内验证
- **流水线寄存器**:IF/ID、ID/EX、EX/MEM、MEM/WB 四组级间寄存器(每组多位 D-FF)
- **寄存器堆**:32×8-bit(或按该实现的位宽),含双读口 + 单写口 + 地址译码
- **程序计数器 PC**:8-bit 寄存器 + +1/分支加法

### ❌ 层 3:存储器(未开始 — 独立大工程)
- **指令存储器**:ROM,存程序。红石 ROM 相对可行(只读,译码器+或阵列)
- **数据存储器**:RAM,读写。红石 RAM 又大又慢,是独立子工程
- 需地址译码、读写口、与流水线时序对接

### ❌ 层 4:时钟与集成(未开始)
- **时钟分发**:流水线需同步时钟;在巨大布局上分发同步时钟本身是难题(时钟偏移)
- **模块集成**:把 6 组合模块 + 时序元件 + 存储按数据通路连起来
- **规模**:2 层架构布局大(alu1 已 300+ 宽);整 CPU 体量极大,/setblock 建造耗时长

## 关键判断

- **组合逻辑**:路已通,布线器差最后一步(层 1)
- **完整 CPU**:还差整整一层时序逻辑(层 2 触发器/寄存器堆)+ 存储(层 3)+ 时钟集成(层 4)
- 现实可交付的里程碑顺序:
  1. 布线器达 0 短路 → 游戏内建成第一个组合模块(alu1/Control)【近期】
  2. D-FF cell 验证 → 单个流水线寄存器 → 寄存器堆【中期】
  3. 指令 ROM + 数据 RAM【中期】
  4. 全 CPU 集成 + 时钟【远期,大工程】
