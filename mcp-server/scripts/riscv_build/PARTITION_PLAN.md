# 分区布线 + 垂直优先 — 架构规划

## 为什么改架构

实测（6 模块泛化）：布通率 60–83%，无一模块 100%；短路 0–25；92 门时 12 分钟。
精简度好（wires/曼哈顿下界 0.48–0.93），说明**画得省，但排不下**。

三个已确诊瓶颈：
1. **贪心不可回退** —— 先布占位、后布失败，无让路机制。negotiated 会震荡（7→13→9→5）。
2. **sink pin 单点单向** —— 输入 pin 是 `repeater[facing=west]`，只能从 (kx-1,kz) 一格喂；被占即无解。
   （source 侧同类问题已用「发布点东移」解决：饥饿 23/31 → 0，是目前最有效的单点改动。）
3. **跨层交付需连续净空** —— 楼梯要一整行 `depth` 格，DOWN 塔要 2×2；密集区都难满足。

现顺序是「先平面、垂直兜底」，恰好把**约束最紧的资源留到最后**。本规划反转它。

## 核心原则

1. **约束最紧者先分配**：垂直交付（塔/楼梯）> 跨区干线 > 区内平面走线。
2. **分区化**：把全局竞争降为局部竞争。区内 net 少、通道相对充裕。
3. **先规划后布线**：先算出每个 net 的「区归属 + 交付方式 + 垂直资源预留」，再实际布。
4. **合并阶段只做跨区**：区内已解决，合并只处理少量跨区干线。

## 阶段划分

### P0 规划（无几何输出，纯决策）
- **分区**：按 x 切成宽 W 的区（W 待定，初值 = 2–3 个 gate 列宽）。
  net 的区 = 其所有 pin 所属区集合。`local`（单区）/ `global`（跨区）。
- **交付方式预选**：对每个 sink 预判需要 平面直连 / 楼梯 / 塔，依据是它与源的区关系和 pin 周边净空。
- **垂直资源台账**：每个 sink 的 feed 列 (kx-1,kz) 及其塔/楼梯所需邻格，登记为**预留**。
  冲突在此阶段暴露（而非布线中途失败）。

### P1 垂直优先布置
- 先把所有需要垂直交付的 sink 的**塔或楼梯建好**（含 cross 层入口），占住连续净空。
- 塔（1×1 UP / 2×2 DOWN，已验证）与楼梯按「所需净空最小者优先」排序分配。
- 冲突时按预留台账换朝向（塔 4 向可旋转）或换 cross 层。

### P2 区内平面布线
- 每个区独立跑现有 y0 Dijkstra，只连区内 net，且**避开 P1 预留的垂直资源**。
- 区内 net 少 → 通道压力小 → 预期布通率显著高于全局贪心。

### P3 跨区干线合并
- `global` net 走 cross 层跨区干线，两端接 P1 已建好的垂直交付。
- 干线只在 cross 层，不与区内 y0 竞争。

### P4 验收
- 双指标：`shorts == 0` **且** `unrouted == 0`。
- 链路电气验证（每 net 驱动源、读所有 sink 响应）。
- MCHPRS 整模块验证在 **Win** 执行（`win_verify.py`，alu1 全量 46.6 s）。

## 复用已验证资产

- `owner3d` 三维占用表 + `_claim3d` / `_free3d`（通用立体 gadget 合法性）
- UP 塔 1×1（`emit_rise` / 偶数火把非反相）
- DOWN 塔 2×2 四朝向（`down_tower_cells_dir`）
- `_lay_cross`（cross 铺设 + 刷新 repeater）
- repeater 定向规则：`facing=X` 表示输入来自 X 侧；转角不可放 repeater
- sink pin 只能从西侧 (kx-1,kz) 喂

## 未定参数（需实测扫描）

| 参数 | 含义 | 备注 |
|------|------|------|
| `W` 区宽 | 分区粒度 | 太小 → global net 暴增；太大 → 退化为全局 |
| `col_gap` | 列间通道宽 | alu1/Control 实测 10 优于 16（省 17% 线长，布通不变）；**Forwarding 等大模块未测，全部测完再定** |
| cross 层数 | 垂直层预算 | 按需最低层起，撞则升 |

## 风险与回退

- 分区可能让原本能全局绕行的 net 变成 global（增加跨区干线）。
  → 以「区内布通率 + 总布通率」双指标衡量，若总量退步则回退。
- P1 先占垂直资源可能过度预留，挤压 P2 平面。
  → 预留只锁必需格（feed 列 + 塔朝向所需邻格），不锁整行。

## 保留的负面结论（勿重复）

1. descent 走廊扩大候选（更多 z 偏移 + x 后退）→ failed 5→8
2. LONG_HAUL 长连接强制上 cross → 布通 24→26 但链路仅 16/26
3. 地下 cross 平面 → 物理可行、wires −16%，但布通 8 vs 5（塔只能向上，两侧总有一侧要楼梯）
4. DOWN 塔优先于楼梯 → failed 5→8（塔要 2×2，此布局下空行比空 2×2 易得）
5. negotiated（软重叠 / 失败优先 + 历史惩罚）→ 震荡，且必带短路
